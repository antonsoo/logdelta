# Example logs

Most files in this directory are **synthetic** — either hand-written or generated by a
committed script — to look like real tool output (pytest, Vite/npm, a Kubernetes container
log stream, a parallel test run) for demos and tests. The HTTP fixtures are instead
captured from a controlled local server with an injected fault. None is production evidence.

| File | What it is |
|---|---|
| `pytest-pass.log` / `pytest-fail.log` | Same pytest suite, one clean run and one with a failing test and its traceback. `pytest-pass.log` also re-runs `test_divide` a few extra times as a stability check, so its baseline has enough repeated `PASSED` history for the NEW VALUE finding's repetition requirement (see the README) to fire on the flip to `FAILED`. |
| `npm-build.log` | A Vite production build. |
| `http-good.log`, `http-good-2.log`, `http-failed.log` | Actual records from [`capture_http.py`](capture_http.py)'s loopback HTTP server: 20 requests per run, with 503 deliberately returned twice in the failed run and a checked process exit of 1. Timestamps/durations are measured; large sequential request IDs are assigned by the fixture. Regenerate with `python examples/capture_http.py`; use `--output-directory` to retain the committed capture. [Field-watch walkthrough](../docs/watched-fields.md). |
| `http-routes-good.log`, `http-routes-good-2.log`, `http-routes-failed.log`, `http-routes-observed.json` | The same server with 20 checkout and 20 maintenance requests per run. Maintenance always returns 503; checkout returns it twice only in the target. The JSON file records what the HTTP client received. Regenerate with `python examples/capture_http.py --scenario mixed-routes`; use `--output-directory` to retain this capture. [Compare within routes](../docs/watched-fields.md#compare-within-routes-or-services). |
| `k8s-service.log` / `k8s-service-incident.log` | A container's stdout/stderr as `kubectl logs --timestamps` would show it: JSON startup line, an access-log line per request, then (in the incident file) a failed DB connection and a Go panic. |
| `large/baseline-{1,2,3}.log`, `large/target-failure.log` | Generated by [`gen_large_fixtures.rs`](gen_large_fixtures.rs) (`cargo run --release --example gen_large_fixtures`): a few thousand lines each, a `pytest-xdist`-style parallel test run (shuffled order, timings, UUIDs, an occasional known-flaky skip) interleaved with ~50 sharded microservices logging one of 8 message kinds. One message's rate deliberately varies a lot across the three baselines (a real flaky signal for `diff`'s multi-baseline down-weighting to suppress); the target buries one content flip (a specific test going from `PASSED` in every baseline to `FAILED`), one removed message, and two brand-new ones among thousands of otherwise-identical lines. |

Try, from the repository root:

```console
$ cargo run --release -- diff examples/pytest-pass.log --target examples/pytest-fail.log
$ cargo run --release -- templates examples/k8s-service.log
$ cargo run --release -- diff examples/k8s-service.log --target examples/k8s-service-incident.log
$ cargo run --release -- diff examples/large/baseline-{1,2,3}.log --target examples/large/target-failure.log
```
